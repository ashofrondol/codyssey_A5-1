## 프로젝트 개요

머신러닝 파이프라인(pipeline, 데이터 전처리 → 모델 학습 → 성능 평가를 하나의 흐름으로 묶은 자동화 시스템)은 대출 심사, 이상 거래 탐지, 불량품 선별처럼 신뢰성이 중요한 곳에 쓰인다. 이 미션에서는 은행의 신용리스크 담당자 입장에서 고객의 대출 승인/거절/보류 정책을 결정하는 AI 모델을 만든다. 명세가 준 코드로 가상의 금융 데이터(신용 점수와 연체 기록)를 생성하고, 사람이 정한 if-else 규칙(규칙 기반 베이스라인, 비교 기준이 되는 가장 단순한 모델)과 머신러닝 모델의 성능을 숫자로 비교한다. 같은 데이터로 **회귀**(숫자 값 예측: 신용 점수)와 **분류**(범주 예측: 연체 여부)를 모두 풀어 보며, 문제 유형에 따라 지표·모델·해석이 어떻게 달라지는지 체감하는 것이 핵심이다. 또한 데이터 불균형(한쪽 정답이 훨씬 적은 상태) 처리, 규제(Regularization, 모델이 학습 데이터에만 지나치게 맞춰지지 않게 가중치 크기를 억제하는 방법), 앙상블(여러 모델을 합쳐 쓰는 방법)을 경험한다.

**핵심 과제** (명세의 "기능 요구 사항")

1. 제공된 코드로 `finance_data.csv`를 생성하고 Git 환경(`.gitignore`)을 구성한다.
2. 규칙 5개 이상의 if-else 베이스라인을 만들고 성능을 측정한다.
3. Scikit-learn `Pipeline`/`ColumnTransformer`로 전처리를 모듈화하고, fit은 Train Set에서만 한다.
4. 회귀(Ridge, Lasso), 불균형을 처리한 분류, GridSearchCV로 튜닝한 앙상블 모델을 만들고 평가한다.

## 개발 환경과 제약 사항

**개발 환경**

- Python 3.10 이상
- 필수 라이브러리: Scikit-learn, Pandas, NumPy, Matplotlib/Seaborn만 사용한다.
- 선택 허용 라이브러리: imbalanced-learn(SMOTE), XGBoost. 사용 시 `requirements.txt`에 버전을 명시한다.

**금지 사항**

- 딥러닝 프레임워크(PyTorch, TensorFlow)는 사용하지 않는다.
- 외부 데이터는 사용하지 않는다.
- 생성된 데이터를 임의로 수정하지 않는다. (의도적인 노이즈와 불균형이 들어 있다)

**데이터셋 조건**

- 반드시 명세가 제공한 코드(`data_gen.py`)로 생성한 데이터를 사용한다.
- 샘플 10,000건, `random_state` 42. 특성 6개(`age`, `annual_income`, `spending_score`, `debt_ratio`, `credit_card_count`, `overdue_count_6m`)와 타겟 2개(`credit_score`: 회귀용, `is_overdue`: 분류용)
- `is_overdue` 비율은 약 10~15%로, 불균형 처리의 효과를 볼 수 있게 설계되어 있다.

**형상 관리**

- 기능 단위(전처리, 모델링, 문서화)로 커밋(Commit) 로그를 남긴다.

### 데이터를 다룰 때 주의할 점

- **데이터를 바꾸지 않는다.** 노이즈와 불균형은 일부러 넣은 것이다. 이상해 보이는 값(예: 소득이 1,500인 행)도 지우거나 고치지 않고, 필요한 처리는 파이프라인 안에서 Train Set 기준으로만 한다.
- **`.gitignore`에 `*.csv`를 넣는다.** 지금 `.gitignore`에는 `*.csv`가 없다. `finance_data.csv`를 만들기 전에 추가해야 실수로 커밋되지 않는다(할 일 1).
- **`credit_score` → `is_overdue` 누수.** `is_overdue`는 `credit_score`가 292 미만인지로 정해진다(그 위로는 연체가 한 건도 없다). 분류 모델에 `credit_score`를 넣으면 정답을 거의 알려 주는 셈이다. [명세에서 확인할 점](#명세에서-확인할-점) 참고.
- **타겟과 상관없는 특성이 있다.** 생성 코드를 보면 `credit_score`는 `annual_income`, `overdue_count_6m`, `debt_ratio`와 노이즈로만 계산되고, `age`, `spending_score`, `credit_card_count`는 어느 타겟에도 쓰이지 않는다. 그래서 Lasso는 이 세 변수의 가중치를 0으로 만들 가능성이 크고, "카드 과다 보유" 같은 규칙은 베이스라인 성능을 올리지 못한다. 버그가 아니라 데이터가 그렇게 만들어진 것이므로, 결과를 해석할 때 이 사실을 근거로 쓴다.
- **코드 주석과 실제 동작이 다르다.** 주석은 "소득이 음수인 경우 0으로 처리"라고 하지만, 코드는 1,500보다 작은 소득을 모두 1,500으로 바꾼다. 또 주석은 "부채 비율이 높으면 연체 확률 증가"라고 하지만, `is_overdue`는 `credit_score`와 무작위 값으로만 정해진다(부채 비율은 `credit_score`를 거쳐 간접적으로만 영향을 준다). 코드를 고치지 말고, README에 해석할 때만 반영한다.
- **연습용 공개 데이터는 섞지 않는다.** 과제 결과표와 그래프는 모두 `finance_data.csv`로만 만든다. 공개 데이터 실험은 이 레포 밖에서 하고, 하더라도 출처와 라이선스를 적는다(예: German Credit은 CC BY 4.0이라 출처 표기가 필요하다).

## 할 일

명세의 기능 요구 사항이다. 끝낸 항목은 `[x]`로 바꾼다.

### 1. 데이터 생성 및 Git 환경 구성

명세가 준 코드로 모두가 같은 데이터를 만들고, 데이터 파일은 저장소에 올리지 않는다.

- [ ] 제공된 [데이터 생성 코드]를 `data_gen.py`로 작성하고 실행하여 `finance_data.csv`를 생성한다.
- [ ] 생성된 데이터(의도적인 노이즈와 불균형 포함)를 임의로 수정하지 않는다.
- [ ] `git init` 후 `.gitignore`를 설정하여 데이터 파일(`*.csv`)이 저장소에 업로드되지 않도록 한다.

### 2. 규칙 기반 베이스라인 구현

머신러닝과 비교할 기준으로, 사람이 생각한 조건문만으로 연체 여부를 예측한다.

- [ ] if-else 조건문을 활용한 규칙 기반 예측 모델을 최소 5개 이상의 규칙으로 정의한다.
- [ ] 베이스라인 모델의 Accuracy, Precision, Recall, F1-Score를 측정한다.
- [ ] 베이스라인 vs ML 모델의 성능 비교표를 README.md에 포함한다.

### 3. 데이터 파이프라인 (Data Pipeline)

전처리 단계를 하나로 묶어 두면 Train과 Test에 똑같이 적용할 수 있다. fit(평균, 범위 같은 기준값을 데이터에서 배우는 것)을 Test Set까지 보고 하면 시험 문제를 미리 본 셈이 되어 성능이 부풀려진다. 이것을 데이터 누수라고 한다.

- [ ] Scikit-learn의 `Pipeline` 또는 `ColumnTransformer`로 전처리 과정을 모듈화한다.
- [ ] 수치형 변수는 대치(Imputation, 빈 값 채우기) 후 스케일링을 적용한다.
- [ ] 범주형 변수는 인코딩을 적용한다.
- [ ] 스케일러와 인코더의 fit은 반드시 Train Set에서만 수행한다.
- [ ] Train/Test 분할 비율 8:2 (stratified random split 권장)
- [ ] `random_state=42` 고정 (필수)
- [ ] Cross-Validation: 5-fold (권장)
- [ ] 전처리/SMOTE/스케일링은 반드시 Train Set에서만 fit한다.

### 4. 모델링 및 성능 최적화

Ridge(L2 규제)와 Lasso(L1 규제)는 가중치가 커지지 않게 벌점을 주는 회귀 모델이다. Alpha는 그 벌점의 세기이며, Lasso는 Alpha가 커지면 일부 가중치를 0으로 만들어 변수를 빼 버린다.

**회귀 모델**

- [ ] Ridge와 Lasso를 모두 적용한다.
- [ ] Alpha 값 변화(0.01, 0.1, 1, 10, 100)에 따른 계수 변화 그래프를 그린다.
- [ ] RMSE, MAE, R² 중 2개 이상을 측정하고 비교표로 정리한다.

**분류 모델**

- [ ] `class_weight='balanced'` 또는 SMOTE를 적용하여 불균형을 처리한다.
- [ ] 연체 확률(0~1)을 출력한다.
- [ ] Confusion Matrix를 시각화한다.
- [ ] ROC-AUC 곡선을 시각화하고 AUC 값을 명시한다.

**앙상블**

- [ ] Random Forest 또는 XGBoost를 적용한다.
- [ ] GridSearchCV로 하이퍼파라미터를 최적화한다. (탐색 가이드: 파라미터당 후보 값 5개 이하 권장, 총 탐색 조합 100개 이하 권장)
- [ ] (권장) 앙상블 모델의 특징 중요도(Feature Importance) 시각화와 해석 3줄 요약을 README.md에 포함한다.

## 명세에서 확인할 점

- **범주형 변수와 결측치가 없다**: 3. 데이터 파이프라인은 "수치형 변수는 대치(Imputation) 후 스케일링을, 범주형 변수는 인코딩"을 요구하지만, 제공된 데이터 생성 코드가 만드는 6개 특성은 모두 수치형이고 빈 값을 만드는 코드도 없다. 인코딩·대치 단계를 어떤 데이터에 적용해야 하는지 확인이 필요하다.
- **분류 입력에 `credit_score`를 넣어도 되는가**: 분류 모델의 입력은 "동일한 고객 데이터"인데, `is_overdue`는 `credit_score` 하위 15% 기준으로 만들어진다. `credit_score`를 분류 특성으로 넣으면 정답을 거의 알려 주는 셈(데이터 누수)이 되므로, 포함 여부를 정해야 한다.
- **비교표 지표가 서로 다르다**: 최종 결과물의 비교표는 "(Accuracy, F1-Score, AUC)", 베이스라인 측정 요구는 "Accuracy, Precision, Recall, F1-Score", 결과 예시 표는 Accuracy, F1-Score, AUC, Recall이다. 또 if-else 베이스라인은 0/1만 내므로 AUC를 어떻게 계산할지 적혀 있지 않다.
- **승인/거절/보류 정책**: 미션 소개는 "대출 승인/거절/보류 정책을 결정"하고 "임계값 설정이 비즈니스 의사결정과 직결"된다고 하지만, 기능 요구 사항에는 임계값을 정하거나 세 가지 정책으로 나누는 항목이 없다.
- **Python 버전 표현이 다르다**: 6. 개발 환경은 "Python 3.10 이상", 7. 제약 사항은 "Python 3.10+ 권장"이다.
